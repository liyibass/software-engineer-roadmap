## 概念說明

### 權重語法在做什麼 🔬

`(word:1.2)` 的實作比你想的簡單：

```
1. 正常把整段 prompt 編碼成向量序列
2. 把 "word" 對應的那幾個 token 的向量，乘以 1.2
3. （多數實作會再做一次正規化，避免整體強度失衡）
```

**就是把某幾個詞的向量「拉長」。** 拉長之後，它在 CFG 的引導方向上佔的比重就變大。

| 語法 | 等於 |
|------|------|
| `(word:1.2)` | 權重 1.2 |
| `(word)` | 權重 1.1 |
| `((word))` | 權重 1.21（1.1 × 1.1） |
| `[word]` | 權重 約 0.909（1 ÷ 1.1） |
| `(word:0.5)` | 權重 0.5（減弱） |

> ⚠️ **注意 ComfyUI 與 A1111 的權重計算方式有細微差異**。同一個 `(word:1.3)` 在兩邊的效果不完全一樣。從別處抄 prompt 時，權重可能要微調。

### 權重的安全區間

實務上的經驗值：

```
0.7 ~ 1.3   ✅ 安全區間，效果可預期
1.3 ~ 1.5   ⚠️ 開始出現副作用（過飽和、構圖被拉歪）
> 1.5       ❌ 色塊崩壞、肢體變形、整張圖被那個概念吃掉
< 0.5       ⚠️ 幾乎等於沒寫
```

**為什麼過高會崩壞**？因為那個向量被拉得太長，在 CFG 的計算裡蓋過所有其他方向——模型每一步都被往同一個極端推，最後超出正常的數值範圍。

> **症狀辨識**：出現大面積的飽和色塊、顏色溢出邊界、人體結構融化——這通常是**權重過高或 CFG 過高**，兩者的症狀很像（機制也確實相關，見 `comfy-2-10`）。

### tag 順序真的有影響嗎 🔬

**有，但沒有社群傳說的那麼強。** 這節要誠實拆解。

#### 機制上的根據（真的存在）

**根據一：CLIP 的注意力是單向的**

CLIP 的 transformer 用的是 causal attention（因果注意力）——**每個 token 只能「看到」它前面的 token**。

```
"1girl, long hair, night park"
 ↑       ↑          ↑
 只看自己  看得到 1girl  看得到前面全部
```

結果是：**排在前面的詞會被後面所有詞「參考」到，所以它對整體語意的影響面更廣。**

**根據二：訓練資料的分布**

Danbooru 的 tag 是有慣例順序的（角色數 → 角色 → 特徵 → 服裝 → 動作 → 背景）。模型在訓練時看到的絕大多數 caption 都遵循這個順序，所以：

> **順序符合訓練分布時，模型的表現最穩定。** 這不是「前面權重高」，而是「這樣寫比較像它看過的東西」。

#### 但影響有多大

⚠️ **這是被誇大最嚴重的部分。** 常見的說法是「前面的 tag 權重高很多」，實際上：

- 把一個 tag 從第 3 位移到第 15 位，**效果差異通常很小**
- 遠小於「把權重從 1.0 改成 1.3」的差異
- 遠小於「換一個 seed」的差異

**誠實的結論**：

| 說法 | 校準後的版本 |
|------|------------|
| 「tag 順序決定權重」 | ⚠️ 過度簡化。順序有影響，但很弱 |
| 「重要的放前面」 | ✅ 合理建議，成本為零，照做就好 |
| 「移動 tag 順序可以精細調整」 | ❌ 不可靠。要調強度就用權重語法 |
| 「順序要符合 Danbooru 慣例」 | ✅ **這條最有價值**——因為符合訓練分布 |

> 你專案文件寫的「順序＝權重：`品質詞, 角色數, 角色特徵, 服裝, 動作, 背景, 構圖`」——**這個順序是對的，但理由不是「權重」，而是「這是 Danbooru 的慣例，模型最熟悉」**。
>
> 結論相同，但理解不同的價值在於：**你知道亂序不會毀掉圖，只是不夠穩**；也知道**不要指望靠移動順序來微調效果**。

### ⚠️ 三個被過度傳頌的技巧

#### 傳說一：一長串「品質詞」是必須的

```
masterpiece, best quality, ultra detailed, 8k, highly detailed,
absurdres, extremely detailed CG unity 8k wallpaper, ...
```

**現實**：

- 對 SD1.5 時代的模型，品質詞確實有明顯效果（因為訓練資料的美學評分標註）
- 對現代的 Illustrious / Pony 系，**多數品質詞的邊際效益很低**，有些甚至已被模型作者訓練成預設行為
- 塞一長串會**吃掉你的 75 token 額度**

> **建議**：留 `masterpiece` 之類一兩個就好，實測有沒有差再決定。你專案的 prompt 就只用 `masterpiece`——**這是對的**。

#### 傳說二：負面詞要塞一長串

下一章專門講這個（`comfy-2-6`、`comfy-2-7`）。**簡短版結論：不要。你的專案已經實測過負面愈長臉愈糊。**

#### 傳說三：BREAK 能完美分隔概念

`comfy-2-4` 講過：BREAK 確實控制分塊位置，但「分開就不會互相污染」的效果實測因模型而異。

> **定位**：這是**流行慣例層級**的技巧，不是必須。prompt 短的話根本用不到。

### embedding 的引用語法

`models/embeddings/` 裡的 Textual Inversion 可以直接在 prompt 裡叫：

```
embedding:easynegative
```

或在某些介面裡直接打檔名。

**它是什麼**：一個「訓練出來的自訂詞」——把某個概念壓縮成幾個 token 的向量。比 LoRA 輕量很多（幾十 KB），但能力也弱很多（只能改變詞的意義，不能改變模型的畫法）。

> 常見用途是負面詞包（`easynegative`、`badhandv4` 這類）。⚠️ 但它們多數是 SD1.5 時代的產物，**在 Illustrious / SDXL 系上效果不明或有害**。用之前要實測。

## 程式碼範例

用偽程式碼看權重的實作：

```
函式 套用權重(tokens, 權重表):

    向量序列 = []
    對於 每個 token：
        向量 = embedding查表(token)

        如果 這個 token 有指定權重：
            向量 = 向量 × 權重           # ← 核心就這一行

        向量序列.append(向量)

    # 多數實作會再做一次正規化，避免整體強度被拉飛
    向量序列 = 正規化(向量序列, 目標=原始平均強度)

    回傳 CLIP的transformer(向量序列)
```

**看得出來為什麼權重過高會崩壞**：那個向量被乘得太長，在後續所有計算裡都佔主導地位。

## 一個實用的優先序

當你想「加強某個效果」時，依**有效程度**排序：

| 手段 | 效果強度 | 副作用 |
|------|:---:|--------|
| 1. **換 / 訓練 LoRA** | 最強 | 成本高 |
| 2. **ControlNet** | 很強（空間上） | 只管空間 |
| 3. **權重語法** `(word:1.3)` | 中 | 過高會崩 |
| 4. **換更精準的 tag** | 中 | 需要知道正確的 tag |
| 5. 移動 tag 順序 | **弱** | 無 |
| 6. 加更多同義詞 | **很弱** | 吃 token 額度 |

> ⚠️ **多數人卡在 5 和 6，反覆微調卻沒效果**。當你發現「調 prompt 怎麼都調不動」時，那就是訊號——**該往上跳一層了**（用 LoRA 或 ControlNet）。
>
> 你專案的髮色問題就是最好的例子：`dark grey hair`、`black hair`、各種權重混合**全都試過，命中率約 15%**。最後的解法不是繼續調 prompt，而是**把髮色訓進 LoRA**（見 `comfy-4-8`）。

## 小練習

1. **測順序的真實影響**：固定 seed，把同一組 tag 用三種不同順序排列，各產一張。**比較差異有多小**——這會校準你對「順序＝權重」的期待。

2. **找出權重的崩壞點**：拿一個 tag（例如 `purple eyes`），權重從 1.0 開始每次 +0.2 產一張，直到 2.0。**記錄從哪個值開始出現異常。** 這個數字對你的模型是有參考價值的。

3. **驗證品質詞**：同 seed，一張帶完整品質詞串、一張只有 `masterpiece`、一張完全不帶。**比較差異**——多數人會驚訝於差異之小。
