# comfy-1-14 📖 custom node 生態導覽：哪些值得裝

> **本章目標**：認識社群節點生態的主要套件，知道各自解決什麼問題。**這是參考章節**——不用全裝，遇到需求再回來查。

## 你會學到

- 幾乎必裝的四個套件，以及它們解決什麼
- 依需求分類的套件地圖（控制 / 後製 / 訓練 / 影片）
- ⚠️ 怎麼判斷一個套件值不值得裝
- 一個提醒：很多「必裝神器」其實內建節點就能做

---

## 概念說明

### 先講一個容易被忽略的事實

網路上的教學常常一開頭就叫你裝十幾個套件。**但 ComfyUI 內建節點的能力比多數人以為的強**。

在裝任何東西之前先問：

```
1. 內建節點做得到嗎？（八成情況做得到）
2. 我是「現在就需要」還是「以後可能用到」？
   → 以後可能用到 = 不要裝
3. 這個套件有多少人在用？
```

⚠️ 回顧 `comfy-0-6`：**每裝一個 custom node，就多一分相依衝突與資安風險**。裝的數量跟環境崩掉的機率成正比。

## 幾乎必裝（四個）

### `ComfyUI-Manager`

管理其他套件的套件。新版 ComfyUI 已內建。

（完整說明見 `comfy-0-6`。）

---

### `comfyui_controlnet_aux`（ControlNet 預處理器）

| | |
|---|---|
| **解決什麼** | 把參考圖轉成 ControlNet 吃的控制圖 |
| **提供什麼** | OpenPose、DWPose、Depth（各種）、Canny、Lineart、Scribble、Normal、Segment… |
| **什麼時候需要** | **只要你要用 ControlNet 就需要** |

ControlNet 模型吃的不是原圖，而是「已經處理成骨架 / 深度圖 / 線稿」的控制圖。這個套件就是做那個轉換的。

> ⚠️ 例外：如果你的控制圖是**自己畫的**（例如你專案的色塊構圖圖），就不需要預處理器——直接把畫好的圖送進 `ControlNetApplyAdvanced` 即可。這也是為什麼 `scene-element.json` 裡沒有預處理器節點。

---

### `rgthree-comfy`

| | |
|---|---|
| **解決什麼** | 大量的介面品質改善 |
| **代表功能** | 進度條、快速 Bypass 開關、Seed 節點、Power Lora Loader（一個節點掛多支 LoRA）、比較用的 image comparer |

**投報率極高**，因為它不改變產圖行為，只讓操作變順。

其中 **Power Lora Loader** 對你特別有用——把「串接三個 LoraLoader」變成「一個節點裡列三行」，測權重矩陣時方便很多。

---

### `ComfyUI-Custom-Scripts`（pythongosssss）

| | |
|---|---|
| **代表功能** | prompt 自動補全（打 tag 時會提示）、節點上顯示圖片預覽、workflow 自動備份 |

**prompt 自動補全對 Danbooru tag 系模型特別有價值**——你打 `pixel` 它會列出所有相關 tag 與使用次數，避免打出模型不認識的詞。

## 依需求分類

### 控制與構圖

| 套件 | 解決什麼 |
|------|---------|
| `ComfyUI_IPAdapter_plus` | IPAdapter（用圖當 prompt），角色 / 風格一致性 |
| `comfyui-tooling-nodes` | 外部程式整合用的工具節點 |
| `ComfyUI-Advanced-ControlNet` | ControlNet 的進階排程（權重隨步數變化） |
| `ComfyUI-Inspire-Pack` | 區域提示詞、進階排程 |

### 後製與修圖

| 套件 | 解決什麼 |
|------|---------|
| `ComfyUI-Impact-Pack` | ⚠️ **自動偵測並修臉 / 手**（FaceDetailer）、遮罩工具、迭代放大 |
| `ComfyUI_essentials` | 大量實用小工具（尺寸計算、遮罩處理、影像運算） |
| `ComfyUI-KJNodes` | 另一組實用工具集（作者 Kijai，影片相關特別多） |
| `was-node-suite-comfyui` | 老牌大全套（⚠️ **非常肥**，裝了會拖慢啟動） |

> **Impact Pack 的 FaceDetailer 值得特別提**：它自動偵測臉部 → 放大 → 重繪 → 貼回去。對「遠景人物臉糊掉」很有效。
>
> ⚠️ 但**對你的像素風產線要小心**：它重繪的臉是高解析度的寫實細節，貼回像素圖上會格格不入。像素風的手部崩壞是通病，**你的專案結論是「小尺寸看不出來，不要在這上面耗時間」**——這個判斷是對的。

### 放大

| 套件 | 解決什麼 |
|------|---------|
| `ComfyUI_UltimateSDUpscale` | 分塊放大（大圖不 OOM） |
| `ComfyUI-SUPIR` | 高品質修復式放大（吃 VRAM） |

### 影片（Part 9 會用到）

| 套件 | 解決什麼 |
|------|---------|
| `ComfyUI-VideoHelperSuite` | 影片載入 / 存檔 / 抽幀（**做影片一定要**） |
| `ComfyUI-AnimateDiff-Evolved` | AnimateDiff 動畫 |
| `ComfyUI-Frame-Interpolation` | 插幀（RIFE） |
| `ComfyUI-GGUF` | 載入 GGUF 量化模型（**12GB 跑大模型的關鍵**） |

### 像素風專用

| 套件 | 解決什麼 |
|------|---------|
| `ComfyUI-Pixelization` 類 | 像素化、調色盤量化 |

> ⚠️ **對你的情況，這類套件要保留態度**。你專案的結論是：現成的 pixelize 工具（每 N×N 取眾數 + 按頻率抽調色盤）**會把眼睛整個吃掉**，重寫後才可用，關鍵在「量出格線的週期與相位」「取格子中央 60% 的中位數」「不做調色盤量化」。
>
> **這種需要精確量測的後製，用外部 Python 腳本做比用節點好**（見 `comfy-1-10` 最後一節）。

## 怎麼判斷值不值得裝

一張檢查表：

| 檢查項 | 標準 |
|--------|------|
| **star 數** | 500+ 相對安全；個位數要看原始碼 |
| **最後更新** | 半年內有更新（生態變化快，沒更新的通常已壞） |
| **Manager 有沒有收錄** | 有收錄代表經過基本篩選 |
| **相依套件多不多** | ⚠️ 相依愈多，衝突風險愈高 |
| **我現在就需要嗎** | 「以後可能用到」= 不要裝 |

---

## ⚠️ 一個常見的浪費：裝了才發現內建就有

| 你想做的事 | 很多人會裝套件 | 其實內建就有 |
|-----------|--------------|-------------|
| 從一批圖裡挑一張 | 某某 selector 節點 | `LatentFromBatch` |
| 縮放圖片 | 某某 resize 節點 | `ImageScale` |
| 兩段 prompt 合併 | 某某 concat 節點 | `ConditioningConcat` |
| 遮罩擴張 | 某某 mask 套件 | `GrowMask` |
| 兩階段生成 | 某某 hires 套件 | 兩個 `KSamplerAdvanced` |

**Part 1 的節點地圖（`comfy-1-6` ~ `comfy-1-10`）就是為了這件事寫的**——知道內建有什麼，才不會白裝一堆東西。

---

## 小練習

1. **盤點你的環境**：列出目前裝的所有 custom node，逐一問「我現在還在用它嗎？」。移除用不到的。

2. **用檢查表評估**：挑三個你裝了但不確定的套件，用上面的檢查表評分。

3. **找出可以被內建取代的**：對照節點地圖，看看有沒有哪個 custom node 的功能其實內建就有。
