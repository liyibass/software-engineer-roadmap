## 概念說明

### 為什麼要自己建基準

網路上的模型評測有三個問題：

| 問題 | 說明 |
|------|------|
| **測試圖跟你無關** | 他們測風景、人像、靜物；你要的是**掛特定 LoRA 的像素風角色** |
| **只看最好的一張** | 沒告訴你「產十張有幾張可用」 |
| ⚠️ **不含你的生態** | 你的角色 LoRA、你的 ControlNet 流程，他們沒測 |

**自己的基準組能回答的問題**：

```
「換這個模型，我現有的產線會怎樣？」
```

這才是你真正要的答案。

---

### 🔧 設計你的測試組

#### 原則：測「你實際會做的事」

```
❌ 不要測：一個女孩站在櫻花樹下（通用測試圖）
✅ 要測：掛 nightheroine-v1 + skormino，832×1216，
        產階段 3 的立繪
```

#### 建議的三組測試

| 測試 | 內容 | 檢驗什麼 |
|------|------|---------|
| **A. 角色立繪** | 掛你的角色 LoRA + 風格 LoRA，全身站姿 | ⚠️ **LoRA 相容性**、角色一致性、格線 |
| **B. 小人 sprite** | 小尺寸、簡單姿勢 | 低解析度下的辨識度、格線 |
| **C. 場景元件** | ControlNet 色塊圖 + `no humans` | ControlNet 相容性、構圖服從度 |

**固定的東西**（每次測試都不變）：

```
seed = 8888（或你慣用的）
prompt = 完全相同的字串
CFG / sampler / scheduler / steps / 尺寸 = 完全相同
LoRA 與權重 = 完全相同
```

**唯一的變數：底模。**

> ⚠️ 這是 `comfy-2-11` 講的同 seed 對照法，套用在模型評估上。

---

### ⚠️ 評估指標：品質不是最重要的

**這是本章最重要的觀念。**

多數人比較模型時只看「哪張圖比較好看」。但對產線來說，更重要的是：

| 指標 | 為什麼比「單張品質」重要 |
|------|----------------------|
| ⚠️ **命中率** | 產 10 張有幾張可用？命中率 8/10 的模型比「偶爾出神作但 2/10」的好得多 |
| ⚠️ **一致性** | 同 prompt 產 4 張，彼此像不像？產線需要可預測 |
| **LoRA 相容性** | 你的角色 LoRA 還能用嗎？觸發詞有效嗎？ |
| **可控性** | 改一個 tag，變化是否符合預期？ |
| 單張品質 | ⚠️ 最後才看 |

> **一個好用的比喻**：你不是在選一張畫，是在選一個**員工**。你要的是穩定交付，不是偶爾天才但常常出錯。

#### 對你的產線，還要加上兩個特別指標

| 指標 | 怎麼測 |
|------|--------|
| ⚠️ **格線保留度** | 量測（`comfy-6-3`）**且放大看臉**（`comfy-6-4` 的教訓） |
| ⚠️ **邏輯解析度** | 人物高度 ÷ 色塊大小，跟 canon 的 145 比（`comfy-2-3`） |

### 🔧 動手：跑一次完整評估

**準備**（一次性投資）：

1. 把三組測試存成 workflow 檔案：`bench-portrait.json` / `bench-sprite.json` / `bench-scene.json`
2. 每個檔案裡的所有參數固定，**只有 checkpoint 節點會被換**
3. 建一個資料夾放產出：`bench/<模型名稱>/`

**執行**：

```
對每個候選模型：
    1. 換掉 checkpoint（其他一律不動）
    2. 三組測試各產 10 張
    3. 填評估紀錄
    4. ⚠️ 放大看臉，不要只看縮圖
```

> **用腳本跑會快很多**。你已經有 `tools/comfy/generate.py` 這種通用執行器——把模型名稱當參數掃過去就好（Part 7 會完整講）。

### 建立你的「模型手感」

除了正式評估，還有一個長期的收穫：**你會開始對模型有直覺**。

具體來說，跑過幾輪之後你會知道：

| 你會知道 | 例子 |
|---------|------|
| 哪些模型偏哪種畫風 | 「這支線條硬，那支偏柔」 |
| 哪些模型對 tag 比較服從 | 「這支你叫它側身它就側身」 |
| 哪些模型愛出特定毛病 | ⚠️ 「這支很愛自己加背景」 |
| 你的 LoRA 在哪些模型上表現最好 | ⚠️ **這是最有價值的** |

> **最後一項值得特別做一次實驗**：你的 `nightheroine-v1` 是在 WAI Illustrious 上訓的，但它在**其他 Illustrious 系模型**上表現如何？
>
> 可能的發現：某個模型讓你的 LoRA 表現更好（因為它的基礎畫風更接近你的訓練集）。**這是零成本的升級機會**——不用重訓 LoRA，只換底模。

## 小練習

1. **建立三個 benchmark workflow**：這是一次性投資，之後每次評估都能用。

2. **測試你的 LoRA 在別的底模上**：找兩三個其他 Illustrious 系模型，用同樣的 LoRA 與參數產圖。**可能會有意外收穫。**

3. **完成一份評估紀錄**：挑一個你一直好奇但沒試過的模型，走完整個流程並填完紀錄表。**體驗一次「有結構的評估」跟「隨便試試」的差別。**
