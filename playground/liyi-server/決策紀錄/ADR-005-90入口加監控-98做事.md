# ADR-005：90 當入口＋監控，98 專心做事

| | |
|---|---|
| **狀態** | ✅ 已核准（2026-11-08），🚧 監控搬家尚未執行 |
| **日期** | 2026-11-08 |
| **延伸** | [實戰筆記 04](../實戰筆記/04-兩台機器的部署分工與三個綠燈陷阱.md) 定的「門 vs 打雜」 |
| **影響範圍** | `90` 新增 Docker 與監控、`98` 的 Prometheus／Grafana 容器、兩台的 runner 資源限制 |

---

## 背景

2026-08-28 定下「**90 是門、98 是打雜**」：90 只放 proxy，98 跑所有東西。當時 98 上只有監控和一個靜態網站。

到 2026-11 月，98 上的東西變成：

| 服務 | 性質 |
|---|---|
| Grafana＋Prometheus＋node_exporter（Docker） | 監控 |
| nginx（Kinto 官網 origin） | 對外網站 |
| 一個 Next.js 網站 :3200（SQLite） | 對外網站，**有資料、有寫入** |
| ComfyUI 任務面板 :8190 | 內部工具，24 小時跑 |
| 3 個 GitHub runner | CI：每次 push 在這台 `npm ci`＋build |

而 90 幾乎是閒的：nginx、cloudflared、Tailscale、node_exporter。兩台規格一樣（4 核、8GB）。

## 問題

**1. 監控跟被監控的東西在同一台。** 98 掛了（當機、硬碟滿、網路斷），Grafana 和 Prometheus 跟著一起掛——**最需要知道「98 掛了」的時候，告訴你的那個也不在了**。實戰筆記 05 那 5 分鐘 98 從網路上消失，監控完全沒有紀錄。

**2. CI 跟對外服務搶資源。** runner 一跑 build，CPU 吃滿幾分鐘，同一台的網站和面板跟著變慢。

**3. 目前沒有任何「網站活著嗎」的監控。** node_exporter 只看主機（CPU、記憶體、硬碟），網站回 500 它不會知道。

## 決定

| | 90（入口＋監控） | 98（做事） |
|---|---|---|
| 對外入口 | cloudflared、nginx proxy、Tailscale | — |
| 監控 | **Prometheus、Grafana、blackbox exporter 搬到這台** | 只留 node_exporter |
| 服務 | — | 網站、任務面板、Kinto origin |
| CI | 不在 98 也行的 runner 可以考慮移過來 | 要本機部署的 runner 留著，**用 systemd 限 CPU／記憶體** |

另外加一個**從外面打的健康檢查**（Cloudflare Health Check 或 UptimeRobot 免費版），補 90 整台掛掉的盲點——監控搬到 90 之後，90 掛了就換成它沒人管。

### 為什麼監控放 90，不放第三台

- 90 本來就閒，規格跟 98 一樣
- 90 是入口，它掛了外面本來就進不來；監控跟入口一起掛，比跟服務一起掛好接受——至少服務壞的時候監控還在
- 第三台（`97`）還沒有，為了監控買一台對這個規模不划算

### 為什麼這不違反「90 只當門」

08-28 那條原則要防的是**內容和狀態跑到門上**：90 沒有網站內容、不 build、不放資料，換掉或重灌都不心疼。監控會帶來一些狀態（Prometheus 的歷史指標、Grafana 的儀表板），但：

- 這些狀態**掉了不影響任何服務**，只是少了歷史圖表
- 跟入口一樣，它的工作是「看著別人」，不是「做事」

所以界線改成：**90 可以放「看」和「轉」的東西，不放「做」的東西。**

### 代價

- 90 要裝 Docker（[monitoring-setup](../../../../monitoring-setup/README.md) 當初刻意不裝）。Docker 的 port publish 會繞過 ufw，90 是對外入口，publish 一律要綁 `127.0.0.1` 或內網 IP
- 監控資料要搬（Grafana 的儀表板、資料源、使用者），搬前要先盤點
- 舊的 98 容器要等新的確認能用才停，中間有一段兩邊都在跑

## 考慮過的選項

| 選項 | 為什麼沒選 |
|---|---|
| 維持現狀，全部在 98 | 上面三個問題都還在 |
| 只加外部健康檢查，不搬監控 | 解決「98 掛了沒人知道」，但看不到掛之前的趨勢（硬碟慢慢滿、記憶體慢慢漲） |
| 用雲端監控（Grafana Cloud 免費版） | 免費額度夠，但等於把主機指標送出家裡；又多一個帳號要管。規模再大再考慮 |

## 實作順序

1. 盤點 98 上 Grafana 的儀表板、資料源、使用者
2. 90 裝 Docker，起 Prometheus＋Grafana＋blackbox exporter（publish 綁 `127.0.0.1`／內網 IP）
3. 新的確認能用（兩台 target 都 UP、儀表板都在）→ 停 98 的舊容器
4. 加網站監控（blackbox 每分鐘打幾個關鍵網址）與警報（網站掛、硬碟 >85%、CPU／記憶體長時間高）
5. 外部健康檢查
6. 98 的 runner 加 `CPUQuota`／`MemoryMax`
7. 清掉 90 上已經沒人用的舊 ssh 隧道

做完更新 [架構現況](../架構現況.md) 與這份的狀態。
